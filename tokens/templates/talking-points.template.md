# Demo talking points — template

Exactly **3 points** per cluster. Each point is a headline you could read
aloud from a slide, plus one supporting fact with a number.

## Shape

```
1. **{Outcome in one plain sentence — no token paths, no jargon}**
   — {number-backed proof: token count, mode count, states covered, before/after}
```

## Rules

- The headline must survive being the only thing on a slide. Token paths and
  technical detail belong in the support line only.
- Default spread across the three points:
  1. **Coverage** — what the cluster now guarantees (scale, modes, brands)
  2. **A decision** — one choice that makes the system better, and why
  3. **What it unlocks** — the next thing this makes possible or easier
- Honest tone: a parked decision can be point 3 ("what's next"), never hidden.
- Numbers over adjectives: "13 tokens × 4 modes" beats "comprehensive".

## Worked example (Accordion-flavoured, illustrative)

1. **Accordion now ships a complete four-mode token set — both brands, light
   and dark, no gaps.**
   — 13 tokens × 4 modes, every value explicitly set; no inherited or implied
   values left.
2. **Disabled styling is handled once, at the wrapper — so nested controls
   can't double-fade.**
   — One opacity treatment replaces per-layer opacity; same pattern as
   Checkbox and Radio Button.
3. **This is the template for the next clusters — the same shape now applies
   to every expandable component.**
   — Kickoff-to-handover ran on the standard cluster recipe; two components
   are queued to reuse it as-is.
